## 2. 目标与范围

### 2.1 本期目标

交付一个**可安装、可长期自用、可开源**的 Android App，功能与 Web 原型对齐，并补齐原型缺失的原生能力：

- 四种打卡类型完整可用：主动 `active`、被动 `passive`、计量 `meter`、周期 `periodic`
- 数据本地 SQLite 持久化，支持导入导出与换机迁移
- 系统本地通知、生物识别应用锁、卡片背景选图
- 无账号、无服务器、无网络依赖

### 2.2 范围边界

| 包含 | 不包含（本期） |
| --- | --- |
| 今日 / 记录 / 我的 三 Tab | 账号、云同步、多端同步 |
| 四种打卡与全部统计口径 | iOS、HarmonyOS 适配 |
| 打卡项管理、预设、主题、经期 | 社交、排行榜、分享 |
| 本地通知、应用锁、选图、导入导出 | 医疗建议、设备数据接入 |
| GitHub Releases 分发 APK | 应用商店上架（另立分支处理合规） |

### 2.3 非功能指标

| 类别 | 指标 |
| --- | --- |
| 启动 | 冷启动进入首页 < 2s（中端机） |
| 交互 | 打卡操作响应 < 100ms，无整页重绘卡顿 |
| 数据量 | 支持 5 年记录（约 1 万条）时统计仍即时返回 |
| 离线 | 全功能离线可用；仅「检查更新」按需联网，失败不影响使用 |
| 隐私 | 数据仅存本机；不接入统计 SDK；不申请非必要权限 |
| 兼容 | minSdk 24（Android 7.0）起，targetSdk 跟随当年 Google Play 要求 |

## 3. 技术选型

### 3.1 路线结论

采用 **Flutter 单代码库重写 UI 与数据层**，不采用 Capacitor 加壳、不采用 React Native。

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| Flutter | **采用** | 单代码库、原生体验好、通知/生物识别/文件选择插件成熟、可开源维护 |
| Capacitor 加壳 | 不采用（长期） | 复用原型成本低，但 WebView 体验、生命周期与原生能力长期受限 |
| PWA | 不采用（长期） | 无法满足系统通知、应用锁、后台可靠性要求 |
| React Native | 不采用 | 团队无既有 RN 资产，重写成本与 Flutter 相当但生态一致性差 |

> 如后续需要「最快出包验证真机」，可另起临时分支做 Capacitor 验证包，不进入主线。

### 3.2 依赖清单

| 能力 | 方案 | 备注 |
| --- | --- | --- |
| 框架 | Flutter + Dart 3 | 单代码库出 Android |
| 状态管理 | `flutter_riverpod` | 全局只用一个方案，不混用 Provider |
| 路由 | `go_router` | 三 Tab + 详情页 |
| 本地数据库 | `drift` + `sqlite3_flutter_libs` | 类型安全、支持版本化迁移 |
| 代码生成 | `drift_dev` + `build_runner` | 表与 DAO 生成 |
| 日历 | `table_calendar` | 记录页月历 |
| 图表 | `fl_chart` | 本周稳定度柱状图 |
| 通知 | `flutter_local_notifications` + `timezone` + `flutter_timezone` | 每日提醒 |
| 应用锁 | `local_auth` | 指纹 / 面容 / 设备凭证 |
| 选图 | `image_picker` + `flutter_image_compress` + `path_provider` | 背景图压缩后存本地 |
| 导入导出 | `file_picker` + `share_plus` | JSON 备份 |
| 日期 | `intl` | 本地化格式 |
| 图标 | Material Symbols（内置字体） | 不额外引入 SVG 资产 |

版本策略：全部锁定到当前 stable 的明确版本号，提交 `pubspec.lock`。

### 3.3 权限清单

| 权限 | 用途 | 备注 |
| --- | --- | --- |
| `POST_NOTIFICATIONS` | 每日提醒 | Android 13+ 运行时申请 |
| `USE_BIOMETRIC` | 应用锁 | 无生物识别时回落设备 PIN |
| `SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM` | 定时提醒 | 优先用 inexact，避免审核敏感 |
| `READ_MEDIA_IMAGES`（或相册选择器） | 选卡片背景 | 使用系统照片选择器可不申请 |
| `RECEIVE_BOOT_COMPLETED` | 重启后恢复提醒 | 可选 |
| `INTERNET` | 检查与下载更新 | 仅访问 GitHub 公开 Release，不采集数据 |
| `REQUEST_INSTALL_PACKAGES` | 拉起系统安装器 | 需用户在系统设置授权「安装未知应用」 |

仅申请网络（`INTERNET`）用于检查与下载更新；不申请位置、通讯录、相机（除非后续加入拍照打卡）。

## 4. 架构设计

### 4.1 分层

```text
UI (features)  →  Riverpod Notifier  →  Repository 接口  →  Drift 实现  →  SQLite
```

硬约束：

1. `features` 只依赖 `repositories` 接口，禁止直接引用 drift 表或 DAO。
2. 统计口径实现为**纯函数**（输入 habits + records + 日期），与 UI、数据库解耦，便于单测。
3. 日期一律使用设备本地时区，`YYYY-MM-DD` 字符串作为日期主键；不使用 UTC 存储日期。
4. 全应用无全局可变单例；状态全部经由 Riverpod Provider 暴露。

### 4.2 目录结构

```text
app/lib/
  main.dart
  app/
    app.dart                 # MaterialApp.router
    router.dart              # go_router 配置
    theme.dart               # 莫兰迪三套主题
  core/
    date_utils.dart          # 日期、周起止、跨日判断
    constants.dart           # 内置项 ID、预设、默认设置
    extensions.dart
  data/
    db/
      database.dart          # AppDatabase、schemaVersion、迁移
      tables.dart            # habits / records / app_settings
      daos/                  # HabitDao / RecordDao / SettingsDao
    models/                  # Habit、DailyRecord、AppSettings、枚举
    repositories/
      habit_repository.dart          # 接口
      record_repository.dart
      settings_repository.dart
      local/                          # drift 实现
    backup/
      backup_codec.dart      # JSON 序列化 / 反序列化 / 校验
  domain/
    stats/
      day_met.dart           # 当日是否达成
      active_stats.dart      # 主动型天数
      passive_stats.dart     # 被动型天数
      meter_stats.dart       # 计量型天数
      periodic_info.dart     # 周期倒计时
      stability.dart         # 本周稳定度
      cycle_info.dart        # 经期推算
  features/
    today/                   # 今日网格、卡片、详情
    records/                 # 稳定度、日历、月度统计
    profile/                 # 项目、经期、模式、隐私、数据
    lock/                    # 应用锁
  shared/
    widgets/                 # 卡片、开关、分段控件、底部弹层、Toast
    theme/
```

### 4.3 状态与渲染

- 每个 Tab 一个 `Notifier`，从 repository 读取一次后按需刷新；写操作走 `Notifier → repository → 刷新自身`。
- 页面不做整页重建；列表项使用 `ref.watch` 精确到卡片级。
- 跨日处理：应用回到前台时比较「上次记录的日期」与「今天」，不一致则刷新今日页并重置计量项展示。
- 提醒条、经期卡、倒计时文案随日期/时间变化，用 `Timer.periodic`（分钟级）刷新，页面不可见时暂停。

### 4.4 导航

| 路由 | 页面 |
| --- | --- |
| `/today` | 今日（Tab 1） |
| `/today/habit/:id` | 打卡项详情 |
| `/records` | 记录（Tab 2） |
| `/profile` | 我的（Tab 3） |
| `/profile/settings` | 设置（隐私 / 外观 / 数据） |
| `/lock` | 锁屏（全屏覆盖） |

底部弹层统一用 `showModalBottomSheet` 封装，不占用路由。

## 5. 数据模型

### 5.1 habits

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | TEXT | PK | 内置项固定 ID，自建项 `custom_<时间戳>` |
| `name` | TEXT | 非空，≤ 8 字 | 名称 |
| `alias` | TEXT | 可空 | 敏感项显示名，默认「自律项」 |
| `type` | TEXT | 枚举 | `active` / `passive` / `meter` / `periodic` |
| `required` | INT | 默认 0 | 早睡为 1，不可关闭 |
| `enabled` | INT | 默认 1 | 是否首页展示 |
| `targetTime` | TEXT | 可空 | 早睡目标时间 `HH:mm` |
| `goal` | INT | 可空 | 计量项每日目标 |
| `unit` | TEXT | 可空，≤ 2 字 | 计量单位 |
| `step` | INT | 可空 | 每次累加值，默认 1 |
| `intervalDays` | INT | 可空 | 周期项间隔天数 |
| `bgPath` | TEXT | 可空 | 背景图本地相对路径 |
| `sensitive` | INT | 默认 0 | 是否敏感项 |
| `sortOrder` | INT | 默认 0 | 首页排序 |
| `createdAt` | TEXT | 非空 | `YYYY-MM-DD`，早于该日期不参与统计 |
| `updatedAt` | TEXT | 非空 | ISO 时间 |

> 与技术路线第 5.1 节一致，并补充 `periodic` 类型；**需求文档 v1.1 必须补齐该类型**。

### 5.2 records

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK AUTOINCREMENT | — |
| `habitId` | TEXT | 外键 habits.id | — |
| `date` | TEXT | `YYYY-MM-DD` | 本地自然日 |
| `status` | TEXT | 可空 | `success` / `fail` / `slip`；计量项为空 |
| `amount` | INT | 可空 | 计量项当日累计 |
| `recordedAt` | TEXT | 非空 | ISO 时间 |

约束：`UNIQUE(habitId, date)`；删除 habit 时默认保留记录（`ON DELETE NO ACTION`），由仓库层显式处理。

### 5.3 app_settings（单行，id 固定为 1）

字段：`strictMode`、`reminderEnabled`、`reminderTime`、`hideSensitiveNames`、`appLockEnabled`、`pinHash`、`gender`、`theme`、`periodEnabled`、`periodStart`、`periodLength`、`cycleLength`。

- `healthIndexMode` 不再是数据库字段，仅在导入旧数据时忽略。
- `pinHash` 保存加盐哈希，不存明文；启用 `local_auth` 后可省略 PIN。

### 5.4 迁移策略

- `schemaVersion = 1` 起步；每次表结构变更递增并提供 `MigrationStrategy.onUpgrade`。
- 迁移前自动导出一次 JSON 备份到应用私有目录（保留最近 3 份）。
- 迁移必须配套升级测试：构造 vN 数据 → 迁移 → 断言数据完整。

### 5.5 默认数据（首次启动）

| 顺序 | ID | 名称 | 类型 | 必选 | 默认启用 | 参数 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `sleep_early` | 早睡 | active | 是 | 是 | `targetTime: 23:30` |
| 2 | `no_fap` | 禁飞 | passive | 否 | 是 | `sensitive: true`，`alias: 自律项` |
| 3 | `no_buffet` | 不吃自助 | passive | 否 | 是 | — |
| 4 | `lean_body` | 薄肌打造 | active | 否 | 否 | — |
| 5 | `water` | 喝水 | meter | 否 | 是 | `goal: 8`、`unit: 杯`、`step: 1` |

自修复规则沿用原型：缺早睡补回；无计量项补回喝水；`no_fap` 强制敏感；敏感项无别名补默认值。

### 5.6 备份格式

沿用技术路线第 7 节：`format: "livebetter"`、`version: 1`，包含 `habits` / `records` / `settings`。

导入校验顺序：

1. 解析 JSON，校验 `format` 与 `version`
2. 兼容「标准格式 / 裸对象 `{habits, records, settings}` / 旧版 `lb.*` 三键」
3. 字段级校验与默认值补齐（未知类型拒绝该条并计数）
4. 按 `habitId + date` 去重，冲突以文件为准
5. 事务内整库替换，失败整体回滚
6. 导入前提示「将覆盖当前数据」，并要求二次确认

图片不进入备份文件，仅保留 `bgPath`；跨设备导入后缺失的图片显示默认底色。

## 6. 业务口径（开发基准）

> 与 Web 原型保持行为一致；第 7 章列出需要修正的偏差。

| 类型 | 当日达成 | 连续天数 | 计入日历 / 稳定度 |
| --- | --- | --- | --- |
| 主动 `active` | 当天有 `success`，否则未达成 | 按自然日连续，可消耗周豁免 | 是 |
| 被动 `passive` | 无 `slip` 即保持 | 破戒当日重新计数，保留最长与累计 | 是 |
| 计量 `meter` | `amount >= goal` | 按达标天数 | 是 |
| 周期 `periodic` | 当天完成即重置倒计时 | 不适用，展示距下次天数 | **否** |

- 温和模式：每自然周 1 次断签豁免，不中断连续但不增加天数；严格模式无豁免。
- 日界：设备本地 00:00；跨日自动进入新一天，被动项自动 +1。
- 幂等：同一项目同一天只保留一条记录；重复打卡提示「今天已经记录过了」。
- 撤销：主动 / 被动删除当日记录；计量减到 0 时删除记录。
- 统计起点：项目 `createdAt` 之前的日期不计入任何统计。
- 文案：不使用「失败」「归零」「你搞砸了」。

## 7. 原型偏差裁决

> 来源：功能文档第 10 章的 15 项偏差。下表决定 Flutter 版的处理方式。

| # | 问题 | 裁决 | 落地版本 |
| --- | --- | --- | --- |
| 1 | 目标时间提示「明天生效」但立即生效 | 改为**立即生效**，文案同步 | M2 |
| 2 | 早睡无补卡窗口与 04:00 截止 | v0.1 按自然日记录；补卡窗口列入 v0.2 | v0.2 |
| 3 | 任意早晨点「我要睡了」都成功 | 限定打卡窗口为**目标时间前 6 小时内**；晚于或过早记录均记 `fail` | M2 |
| 4 | 等于目标分钟时文案与判定不一致 | 统一用 `<=`，文案同源计算 | M2 |
| 5 | 应用锁提示「下次生效」但立即出现 | 改为**立即生效**，使用真实 `local_auth` | M5 |
| 6 | 被动项创建当天立即 +1 | 从创建**次日**起计 | M2 |
| 7 | 只能关闭不能删除 | 补充删除入口，删除时二次确认并选择是否保留历史 | v0.2 |
| 8 | 敏感项别名不可修改 | 支持编辑别名 | v0.2 |
| 9 | 提醒只统计主动型未完成 | v0.1 保持原逻辑；v0.2 补齐计量型未达标 | v0.2 |
| 10 | 记录页无单项目历史明细 | 增加项目维度历史视图 | v0.2 |
| 11 | 首页卡片无快捷打卡 | 保持现状（防误触） | — |
| 12 | 无数据导出 / 导入 | 首版必须提供 JSON 导入导出 | M5 |
| 13 | 演示数据文案 30 天、实际 34 天 | 统一为 34 天 | M4 |
| 14 | 页脚版本标识滞后 | 版本号从 `package_info_plus` 读取 | M6 |
| 15 | `healthIndexMode` 冗余 | 移除字段，导入时忽略 | M1 |
| 16 | 内置「填入演示数据」入口 | 正式版移除示例数据生成，统计只反映真实打卡 | M7 |

### M8 应用内更新

> 目标：用户在应用内感知新版本并完成升级；检查失败不打扰、不影响离线使用。
>
> 方案对比：
>
> | 方案 | 结论 | 说明 |
> | --- | --- | --- |
> | 仅检查 + 跳转 Release 页 | 保留为兜底 | 只需 `INTERNET`，不申请安装权限 |
> | 应用内下载 + 校验 + 拉起系统安装器 | **采用** | 需 `INTERNET`、`REQUEST_INSTALL_PACKAGES` 与 `FileProvider` |
> | Google Play 内更新 | 不适用 | 分发渠道为 GitHub Releases |
> | 静默安装 | 不可行 | 需要系统签名或 Root |

- [x] 更新源与版本比较：读取 GitHub Releases `releases/latest` 的 tag 与资产清单，`package_info_plus` 取当前版本做语义化比较（含 buildNumber）；启动检查按 24h 节流，超时、限流、解析失败一律静默
- [x] 检查更新入口：设置页新增「关于与更新」（当前版本 + 检查更新）；有新版时弹层展示版本号、更新说明、APK 大小，无新版给轻提示
- [x] 下载与校验：流式下载到缓存目录并展示进度；读取 Release 的同名 `.sha256` 校验，限定 HTTPS 域名与最大文件大小，失败删除临时文件并提示重试
- [x] 安装拉起：新增 `FileProvider` 与 MethodChannel（`ACTION_VIEW` + `application/vnd.android.package-archive`）；未授权「安装未知应用」时跳系统授权页；ABI 不匹配时提示改走 Release 页手动下载
- [x] 权限与隐私：清单新增 `INTERNET` 与 `REQUEST_INSTALL_PACKAGES`（仅更新使用）；隐私政策与 README 同步「仅访问 GitHub 公开 Release，不上传任何数据」；离线功能保持可用
- [x] 测试：版本比较、校验和、下载异常单测；更新源可注入，覆盖无新版 / 有新版 / 校验失败；发版后用旧版实测完整升级链路

完成标准：旧版在模拟器检测到新版后可下载、校验并拉起系统安装器完成覆盖安装；断网或无新版时无打扰；README 与隐私政策口径一致。

## 10. 质量保障

### 10.1 测试策略

| 层级 | 范围 | 要求 |
| --- | --- | --- |
| 单元测试 | 统计引擎、日期工具、备份编解码 | 覆盖四种类型、豁免、跨月、跨年、边界分钟 |
| 组件测试 | 卡片、弹层、设置行 | 关键交互与状态 |
| 迁移测试 | drift schema 升级 | 每次版本变更必测 |
| 集成测试 | 打卡 → 统计 → 重启保留；导出 → 导入还原 | 发版前必须通过 |
| 手工验收 | Android 14 模拟器（x86_64 release 包） | 按第 12 章清单执行 |

### 10.2 代码质量

- `flutter analyze` 零 warning 作为合并门槛。
- 统计逻辑禁止写在 widget 内；所有口径函数可独立调用。
- 提交前跑 `dart format`。
- 依赖升级单独提交，不与功能混在一起。

### 10.3 性能

- 首页只查询当日所需记录（按日期索引），不做全表扫描。
- 日历只计算可见月份。
- 背景图压缩到长边 ≤ 1080px 且 ≤ 300KB。

## 12. 验收清单（发版前，Android 14 模拟器 release 包）

> 无真机环境，验收统一在 Android 14 x86_64 模拟器跑 release 包执行；清单 15 条不变。

1. 首次安装无需配置，首页显示早睡卡片并可完成打卡。
2. 早睡早于目标时间记为成功，晚于目标时间记为未达成。
3. 目标时间可调 21:30–24:00，改后立即生效且文案一致。
4. 被动项连续天数正确；破戒后重新计数，最长与累计保留。
5. 计量项 +1 累加，达标提示正确，可撤销一次。
6. 周期项完成打卡后倒计时重置，且不计入稳定度与日历。
7. 温和模式每周 1 次豁免生效，严格模式断签归零。
8. 记录页月历色阶与月度统计正确，未来日期不可查看。
9. 隐藏敏感项名称后，首页与详情均显示别名。
10. 应用锁开启后重新进入需生物识别 / PIN 解锁。
11. 新建自定义项目后立即出现，重启后保留。
12. 关闭项目后历史保留，且不再计入统计。
13. 导出 JSON 后清除数据，再导入可完整还原。
14. 通知在设定时间送达，重启手机后仍有效。
15. 清除全部数据后回到默认 5 项。
